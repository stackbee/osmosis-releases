Lakeflow Jobs の構成要素 — ジョブ・タスク・DAG・コンピュート

覚えるべき基本概念はジョブとタスクの2つだけです。 そこに依存関係の組み方（DAG）、制御フローとトリガー、 そして費用に直結するコンピュートの選び方が乗ります。

ジョブとタスク1つのジョブが1つ以上のタスクを持つ
ジョブ
スケジューリング・調整・実行のための主たるリソース。ワークフロー全体を入れる容器。
タスク
ジョブの中の仕事の1単位。ノートブック・スクリプト・クエリなどを実行する。実際に働くのはこちら。

タスクの種類

分類タスクの種類
コードDatabricks ノートブック（対応言語すべて） / Python スクリプト / Python Wheel / Java JAR / Spark Submit
SQL・変換SQL ファイルとクエリ / Spark Declarative Pipelines / dbt
可視化AI/BI ダッシュボード / Power BI 連携

対応言語は5つ — Python・SQL・Scala・R・Java（JAR 経由）。

設定項目はタスクの種類で変わる

コードへのパス、ライブラリの追加、パラメータ、通知、再試行ポリシー。 選んだタスクの種類によって出てくる選択肢が変わります。 ノートブックタスクならソースのパスとコンピュート設定、 SQL タスクならクエリと実行する SQL ウェアハウスの指定です。

依存関係が作る形順序は並べるのではなく、依存から導かれる
頭文字意味効いてくるところ
Directed有向。それぞれの辺に曖昧さのない向きがあるどちらが先かが決まる
Acyclic非巡回。循環を含まない含んでいたら永久に終わらない
Graph頂点が辺で繋がった集まり枝分かれと合流を表せる

組む方法は4つ — Databricks UI・API・SDK・Databricks Asset Bundles。 やることは1つで、タスクの依存関係を設定するだけです。

よく出る3つの形

形かたち使いどころ

ファネル複数 → 1点に集まる複数データソースからの収集

6つを2つに畳む

前半3つがこちらから起動するもの、後半3つが向こうから来たら動くもの。 この分け方で整理すると覚えやすくなります。

どのコンピュートで動かすか費用に直結する。落とし穴が1つ
コンピュート向いている用途特徴
Interactive Cluster
（all-purpose）		 開発・アドホック分析・データ探索 複数ユーザーで共有できる。本番では使わない（費用効率が悪い）
Job Cluster 本番・運用 約50%安い（ジョブ終了で停止するため）。ただしクラウドの起動時間がかかる。タスク間で再利用可
Serverless 本番全般 フルマネージド。起動が速くオートスケール。最適化が既定で入り TCO が下がる
SQL Warehouse SQL クエリ・ダッシュボード・BI 既定でサーバーレス。Intelligent Workload Management で高同時実行＋低遅延。自動起動/停止

いちばんの落とし穴

Interactive Cluster を本番に使わないこと。 共有できて手軽なので流用されがちですが、終了時に停止しないため費用効率が悪い。 試験でもここが問われます。
