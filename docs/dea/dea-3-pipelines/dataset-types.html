データセットの3種類 — ストリーミングテーブル・マテリアライズドビュー・ビュー

宣言的パイプラインが扱うデータセットは3種類。性質が明確に違うので、 取り違えるとパイプライン全体が意図と違う動きになります。 一言でいうと 追記していくもの / 結果を保つもの / 保存しないもの。

このコースで作るもの1つのパイプラインに3つの流れ

出発点はクラウドストレージの JSON ファイル（実際の Lakeflow は多くの形式を扱えます）。

流れBronzeSilverGold
注文 orders_bronze ST orders_silver ST gold_orders_by_date MV（日付ごとの注文数）
ステータス status_bronze ST status_silver full_order_info_gold MV（注文と結合）
＋ cancelled_orders / delivered_orders
顧客 customers_bronze customers_bronze_clean → type1_customers_silver CDC で更新を追跡

3つとも Bronze → Silver → Gold という同じ形をしています。

3種類の性質まずここを一言で持つ

ストリーミングテーブルSTREAM を書かないと増分にならない

Streaming Table構文

CREATE OR REFRESH STREAMING TABLE orders_bronze
AS SELECT * FROM STREAM read_files(
  '/Volumes/.../orders', format => 'json'
);

STREAM という語が効いている

増分のストリーミング読み取りを有効にするには FROM STREAM read_files() と書く必要があります。 この STREAM がチェックポイントを有効にします。書き忘れると増分になりません。

性質中身
増分処理のモードバッチでもストリーミングでも可。ファイルは正確に1回だけ処理される
更新のしかた更新のたびに、ソース側に追加されたデータが追記される
Auto Loader との関係この構文は Auto Loader を使っている。新しいファイルを自動で追跡
二重読み取りファイル名は1度しか読まれないことが保証される

マテリアライズドビューGold 層だけのものではない

Materialized View構文

CREATE OR REFRESH MATERIALIZED VIEW gold_orders_by_date
AS SELECT order_date, count(*) AS orders
FROM 2_silver_db.orders_silver
GROUP BY order_date;

誤解しやすい点

マテリアライズドビューはパイプラインのどこでも使えます。Gold 層専用ではありません。 変換・集計・遅いクエリの事前計算・頻繁に使う計算、どこにでも置けます。

性質中身
更新のしかた更新のたびに、上流の変化を反映してクエリの結果が再計算される
保守パイプラインが自動的に作成・更新する
増分更新該当する場合は増分で更新され、全部を作り直さずに済む（Serverless 対応）
誰が決めるかコストベースの最適化器が、増分にするか完全に再計算するかを判断する

前回の言い方を正確にすると

前回「MV は全体を処理する」と言いましたが、正確には 全体に対して正しい結果を保証するのが MV で、その実現手段（増分更新か完全な再計算か）は最適化器が決めます。 結果の正しさが約束されていて、手段は任せる — これが宣言的ということです。

Temporary ViewView
寿命パイプラインの実行の間だけ実行のあとも残る
Unity Catalog登録されないオブジェクトとして登録される
構文CREATE TEMPORARY VIEWCREATE VIEW
使いどころ内部の、利用者に見せない中間処理実行後も参照させたいもの

制約が2つ

1. パイプラインが Unity Catalog のパイプラインである必要があります。
2. ビューはストリーミングのクエリを持てず、パイプラインのストリーミングのソースとしても使えません。

どちらも OR REFRESH を付けません。ここがテーブル系との書き分けです。

DLT → SDP の構文の変化

旧（DLT・非推奨）新（SDP）
CREATE OR REFRESH STREAMING LIVE TABLECREATE OR REFRESH STREAMING TABLE
CREATE OR REFRESH LIVE TABLECREATE OR REFRESH MATERIALIZED VIEW
CREATE LIVE VIEW / CREATE TEMPORARY LIVE VIEWCREATE VIEW / CREATE TEMPORARY VIEW

覚え方は1つ

LIVE という語が消えた。 中身の意味と機能は同じで、旧構文も後方互換のためそのまま動きます。 ただし新しいパイプラインでは新しい構文を使ってください。
