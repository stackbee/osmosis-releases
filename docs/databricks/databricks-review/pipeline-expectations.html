Pipeline Expectations

Expectations は、Lakeflow Pipelines の中で「このデータはこの条件を満たしていてほしい」という品質ルールを定義する仕組みです。 条件を書く場所であると同時に、違反したときにどうするかを書く場所でもあります。

品質ルールを宣言として書く今回の主題

流れは単純です。データが入ってくる。Expectation が条件を確かめる。その結果として、通すか、落とすか、止めるかが決まります。

隣の回との境界
宣言的パイプラインそのものの定義方法は第15回。ここは中に置く品質チェックだけ

何をチェックするのか条件の書きどころ

条件には、そのテーブルにとっての当たり前を書きます。例えば注文データなら、こうなります。

条件何を守っているか
order_id IS NOT NULL注文を識別できない行を、注文として扱わない
amount >= 0金額が負のままの行を、正常な行と同じ扱いにしない
country IN ('JP','US','DE')決められた値のどれかであること。集合を明示する

条件そのものは、ふだん書いている条件式と同じです。新しい言語を覚える必要はありません。名前を付けた制約として書き、そこに違反時の挙動を添えます。

CONSTRAINT valid_order EXPECT (order_id IS NOT NULL)
  [ ON VIOLATION DROP ROW | ON VIOLATION FAIL UPDATE ]   -- 省略時は記録のみ。行はテーブルに残る

三つの代表的な動きこの回の核

落とし穴。何も指定しなければ既定は記録するだけで、違反した行はテーブルに残ります。「書いたのだから弾かれる」と思い込むのが典型的な誤りです。

まず観測したいときは警告だけケース1 — 金額が負でも止めたくない

 
amount < 0   →   WARN   →   Pipeline は継続
条件
amount >= 0
違反行
そのままテーブルに入る。落ちない
得られるもの
違反が何件あったかの記録

まず品質状況を観測したい場合に向きます。 いきなり落としたり止めたりすると、何がどれだけ壊れているのか分からないまま、処理の結果だけが変わってしまいます。 新しくルールを入れるときは、この形から始めて、件数を見てから次へ進むのが安全です。

不正な行だけ落とすケース2 — 不正行だけ除外したい

 
order_id IS NULL   →   DROP   →   正常行だけ Silver へ
条件
order_id IS NOT NULL
違反行
その行だけ落ちる。Pipeline は止まらない
向く場面
壊れた行は少数で、下流に流したくない。でも処理全体は動かし続けたい

落とした行が何件あったかは、やはり記録されます。黙って消えるわけではありません。 ここが、次に見る単純な絞り込みとの分かれ目になります。

重大なら処理全体を止めるケース3 — 重大な品質問題

 
business_date IS NULL   →   FAIL   →   Pipeline Update 失敗

この列が NULL だと、日付で切る集計も、日付で並べる処理も、どれもおかしくなります。 1行でも混ざったら、続けても意味がありません。 だから落とすのではなく、止めます。落としてしまうと、その行が無かったことになったまま下流が動いてしまうからです。

問題文にこう書いてあったら選ぶ動き
品質違反レコードを記録したい / まず観測したいWARN
不正行だけ除外したい / 正常行だけ Silver へ上げたいDROP
品質違反なら Pipeline を止めたい / 1行も許さないFAIL

単なる絞り込みとの違いWHERE との差 — 試験で問われる形

単純な WHERE amount >= 0 でも不正データは除外できます。出来上がったテーブルだけ見れば同じに見えます。 では何が違うのか。

どの層で適用するかBronze / Silver との相性

ただし、どこで適用するかは要件次第です。取り込む時点で明らかに壊れているものを止めたい、という要件もあります。 試験では「データ品質ルールを適用したい」＝ Silver を答えの軸にしてください。

試験ではこう問われるDEA 試験ポイントと覚え方

「品質違反レコードを記録したい」「除外したい」「品質違反なら Pipeline を止めたい」という問題なら、 Expectations を考える。そのうえで、3つの動きのどれを選ぶかまで決めます。

覚え方

Expectation = データに対する健康診断ルール

健康診断なので、まず測ります。測った結果をどう扱うかは別の判断です。 所見を書いて終わりにするのか（WARN）。その項目だけ除くのか（DROP）。手術のためにいったん全部止めるのか（FAIL）。

条件を書くことと、違反時の挙動を決めること。この2つが別だと分かっていれば、この論点は落としません。
