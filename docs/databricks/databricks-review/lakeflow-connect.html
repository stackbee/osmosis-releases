Lakeflow Connect

Lakeflow Connect は、Databricks へ外部データを取り込むためのコネクタ群・取り込みレイヤーです。 この回は「それが何か」ではなく、他の取り込み方式とどう選び分けるかに絞ります。

入口を標準化する層一言でいうと

 
External Source
   ↓
Lakeflow Connect
   ↓
Databricks / Unity Catalog

対象になるのは、ファイルとして置かれるものだけではありません。接続して取りにいく側のソースまで含めて、入口を1か所に寄せる層です。

入り方対象になるソース
置かれるのを拾うCloud Storage / Local Files
接続して取りにいくSaaS アプリケーション（Salesforce・Workday など） / RDBMS（SQL Server など） / Message Bus

自作で書くか、寄せるかなぜ使うのか

これまでの学習では、REST API や JDBC を自分で書いて取り込む方法も見てきました。 Lakeflow Connect は、可能であればよりマネージドなコネクタを使い、取り込み実装や運用負荷を減らす方向の選択肢です。

やり方自由度実装・運用
自作 requests / JDBC高い接続・差分・再試行・スケジュールまで自分で持つ
Lakeflow Connect対応ソースの範囲対応ソースならマネージドに寄せられる

マネージドの階段Managed と Standard

コネクタが効く二つの例具体例 1 / 2
ソースやりたいこと流れ
Salesforce顧客・商談データを取り込みたいSalesforce → Managed Connector → Unity Catalog Table → Silver / Gold
SQL Server業務 DB の更新データを継続的に取り込みたいSQL Server → incremental ingestion → Lakeflow Connect → Delta Table

どちらも共通しているのは、問題文にソースの名前が具体的に書かれていることです。 それが主要な SaaS や業務データベースなら、この形を思い出してください。

コネクタが無いとき具体例 3

対応する Managed Connector がない、特殊な独自 API のケースです。この場合は REST 取得コードや独自 Pipeline を検討します。

コネクタがあるかどうか。それがそのまま分岐になります。 マネージドに寄せられない側に落ちたことが分かれば、あとは自分で書く話に切り替わります。

Auto Loader との違い優劣ではなく軸
扱う対象位置づけ
Auto LoaderCloud Object Storage 上の新着ファイルファイル取り込みの強力な仕組み
Lakeflow ConnectSaaS・DB・メッセージバスなど複数種類のソース外部ソースから Databricks へ入れるための、より広い入口

Auto Loader は主に増分でファイルを拾う仕組み、Lakeflow Connect はもっと広い概念の取り込み製品群です。 並べて優劣を比べる相手ではなく、軸が違います。

どこで分かれるか選び分けの分岐

試験でどう問われるか逆引きと覚え方
問題文の書かれ方答え
Salesforce や DB など、標準コネクタが存在する外部システムから取り込みたいLakeflow Connect を疑う
Cloud Storage 上の新着ファイルを増分で読みたいAuto Loader が有力
対応 Managed Connector がない独自 APIREST 取得コードや独自 Pipeline

Lakeflow Connect = Databricks への入口を標準化する

ソースの名前が書いてあれば、まずコネクタを疑う。ファイルの新着なら Auto Loader。 この二択を先に切ってから、マネージドの階段を降りてください。
