一つのプロジェクトにまとめる何をまとめるのか

 
プロジェクト
├─ databricks.yml
├─ src/
│   ├─ notebook.py
│   └─ transform.py
└─ resources/
    ├─ jobs.yml
    └─ pipelines.yml

コードと Databricks リソース定義を、同じプロジェクトとして扱います。 ここが出発点です。片方だけを Git に入れても、あるべき姿は再現できません。

中心にある設定ファイルdatabricks.yml

Bundle の中心となる設定ファイルです。bundle にプロジェクトの名前、targets に環境を書きます。

bundle:
  name: sales-etl
targets:
  dev:  { mode: development }
  prod: { mode: production }

環境ごとにモードを書き分けると、同じ定義から出し分けができます。 ここでは「バンドルが環境ごとの差分を持てる」という点だけ押さえてください。環境の分け方そのものは ep018 で扱います。
