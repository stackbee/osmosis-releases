AI エージェントもデータ利用者になる

OpenAI と Databricks の組み合わせで特に面白いのは、人間だけでなく AI Agent も Unity Catalog で管理されたデータを利用する主体になること。 AI Agent が高度になるほど、データガバナンスの重要性は下がるのではなく、むしろ上がります。

一言でいうと利用主体が人間から AI Agent へ広がる

前回までで、Unity Catalog とメダリオンアーキテクチャという土台を見ました。この回は、その土台の上にAI Agent という新しい利用者が乗ったときに何が要るかを見ます。

PII を読んでよいかMask / Row Filter / ABAC
どのデータを使ったかLineage / Audit

向きが逆になる

AI Agent が高度になるほど、データガバナンスの重要性は下がるのではなく、むしろ上がります。人間なら「これは見ないでおこう」と判断できたところを、Agent は権限があれば読みます。判断を人に任せられない分、経路の設計そのものに寄せる必要があります。

RBAC / ABAC との接続主体側の権限 ＋ データ側の属性

用語そのものはキーワード集の回で扱いました。ここで見ているのは、それらが AI Agent 時代にどう組み合わさるかという配線のほうです。

OpenAI と Databricks の双方向関係使うだけでなく、取り込む

Databricks から OpenAI モデルを利用するだけではありません。OpenAI 側の組織管理データ、つまり usage、cost、audit logs などを、Lakeflow Connect の OpenAI Connector で Databricks に取り込む仕組みも提供されています。

DEA 学習としてのポイントキーワードが一本につながる

この事例を見ると、DEA の学習で別々に覚えていたキーワードが、一本につながります。ばらばらの用語集ではなく、1つの経路の部品として並べ直せる、というのがこの回の収穫です。
