PySpark の join を図解で理解する

on の書き方ひとつで、結合後に残る列が変わります。 文字列で渡せば1つにまとまり、条件式で書けば両方残ります。

join の基本の考え方この回で使う2つの表

PySpark の join() は、SQL の JOIN と同じ考え方で DataFrame 同士を結合します。 この回では、注文を表す orders と、顧客マスタを表す customers という 2つの表を例に使います。

order_idcustomer_idamount
10111200
1022800
10331500
customer_idcustomer_name
1佐藤
2鈴木
4高橋

on の書き方で残る列が変わる今回いちばんのポイント

同じ名前のキー列を結合する場合は、文字列で指定できます。

orders.join(customers, on="customer_id", how="inner")

この場合、customer_id は結合キーとして1つにまとまります。

一方、左右で列名が違う場合は条件式で指定します。

orders.join(customers, orders.cust_id == customers.customer_id, "inner")

この場合、cust_id と customer_id の両方が結果に残ります。 不要なら、あとで select() や drop() で整理します。

ここが目玉

この違いは他の回では扱いません。on の書き方だけで結合後の列構成が変わる、というのが今回のいちばんのポイントです。

inner は共通部分だけ残す両方にある行だけ

 
orders.join(customers, on="customer_id", how="inner")
order_idcustomer_idamountcustomer_name
10111200佐藤
1022800鈴木

結果は2行です。注文101は顧客1の佐藤さん、注文102は顧客2の鈴木さんです。 顧客3の注文103は、customers に存在しないため消えます。

覚え方は、inner = 両方に存在する共通部分だけです。

left は左側を守る事実データを落とさない

 
orders.join(customers, on="customer_id", how="left")
order_idcustomer_idamountcustomer_name
10111200佐藤
1022800鈴木
10331500NULL

結果は3行になります。右側に一致するデータがなくても、 左側の orders は消えません。合致しない行は customer_name が NULL になります。

落としたくないときに使う

売上やトランザクションのように左側の事実データを落としたくない場合によく使います。 覚え方は、left = 左を守るです。

cross は全組み合わせを作る要点だけ・詳細は次回

日付マスタが3行、店舗マスタが2行あるとき、crossJoin の結果は 3 × 2 で6行になります。

dates.crossJoin(stores)

全日付 × 全店舗の枠を先に作ってから実績データを left join すると、 売上が0の日や店舗も含めた集計表を作れます。

broadcast は実行方法のヒント要点だけ・詳細は次々回

broadcast() は inner や left のような結合の種類ではなく、 結合をどう実行するかを Spark に教えるヒントです。

orders.join(broadcast(region_master), on="region_id", how="left")

大きい表と非常に小さい表を結合するとき、broadcast() を使うと 小さい方の表を各ワーカーへ配布できます。ネットワーク越しの大量移動が減るため、 JOIN が高速化できる場合があります。

試験に効く覚え方4つで押さえる
結合一言
inner共通部分だけ
left左を守る
cross全組み合わせ
broadcast小さい表を配ってシャッフルを減らす

一言で言えば

特に重要なのは、broadcast() は JOIN の種類ではなく、 JOIN をどう実行するかの最適化ヒントという点です。

全組み合わせを作る cross join の詳しい話と、 小さい表を配る broadcast join の詳しい話は、それぞれ次回以降で扱います。
