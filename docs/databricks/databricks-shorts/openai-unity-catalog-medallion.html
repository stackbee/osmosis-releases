OpenAI に学ぶ Unity Catalog とメダリオン

大量のプロダクトデータを Delta Table に置き、Unity Catalog でガバナンスしながら、多数の社内ユーザーやシステムから安全に利用できる状態を作る。 用語の定義ではなく、大規模環境で Medallion と Unity Catalog がどうつながるかを事例として見ます。

今回のテーマ置く・統制する・使わせる

用語そのものは DEA キーワード集の回で扱いました。ここで見るのは、大規模な環境で二つがどう組み合わさるかという事例のほうです。

全体像は Medallion そのものBronze → Silver → Gold

段ごとに 何をしたデータかが決まっているので、増えても迷子になりません。ゴールドの先に利用者が並ぶところまでが一本の流れです。

Unity Catalog が重要な理由「テーブルがある」だけでは足りない

利用者やデータ量が増えるほど、「テーブルがある」だけでは不十分になります。必要になるのは、次のガバナンスです。

課題Unity Catalog の役割
誰が何を読めるかAccess Control / GRANT / Policy
データがどこから来たか / 誰が何をしたかLineage ・ Audit / Logging
センシティブデータをどう扱うかTag / Mask / Filter / ABAC（次回で詳しく）
大量のデータ資産をどう整理するかCatalog / Schema / Table

単なる「テーブル一覧」ではない

OpenAI のように社内利用者が多い環境では、Unity Catalog はデータ利用の統制レイヤーとして機能します。ここが今回のいちばんの見どころです。

DEA とのつながり別々の機能ではなく、一体として使う
DEA で学ぶもの基盤での受け持ち
Delta Lake信頼できるテーブル
Unity Catalog誰が・何を・どう利用できるかを管理
Medallion Architectureデータを段階的に整理
Databricks SQL / Spark分析・加工・利用

これらは別々の機能ではなく、実際のデータ基盤では一体として使われます。試験勉強では章が分かれていますが、現場では同じ一枚の絵の上に乗っています。

覚え方持つ / 育てる / 使わせる
Delta Lake
データを信頼できる状態で持つ
Medallion
データを段階的に育てる
Unity Catalog
育てたデータを安全に使わせる

3つの動詞で並べる

持つ / 育てる / 使わせる。こう並べておけば、どれがどこを受け持っているかを取り違えません。OpenAI 事例は、この3つが大規模環境でどうつながるかを見る具体例として非常に分かりやすいものです。
