Declarative Pipelines と Jobs の役割分担

中身と依存関係は Declarative Pipelines、起動とスケジュールは Jobs。 この境界だけ押さえれば、試験でも実務でも迷いません。

中身と起動を分ける覚え方はこれで十分

Declarative Pipelines は、データ処理の中身や依存関係を定義する仕組みです。 一方で Jobs は、その処理をいつ起動するか、どう実行するかを管理する仕組みです。

何を作り、どう依存するかPipelines の担当範囲

たとえば Bronze → Silver → Gold を作りたいとします。 Declarative Pipelines が担当するのは、次の部分です。

Bronze が先 / Silver は Bronze の後 / Gold は Silver の後
定義するものこの例では
何を作るかBronze Silver Gold の3つのテーブル
どう依存するか上流が終わってから下流、という順序

ここに時刻は一切出てきません。出てくるのは処理内容と依存関係だけです。

いつ動かすかは別の仕組みそこで Jobs を使う

「毎朝 6:00 に動かしたい」「毎時間動かしたい」「月曜日だけ動かしたい」—— こうしたスケジュール管理は Declarative Pipelines の役割ではありません。

仕組み持っている問い
Declarative Pipelinesこのデータ処理をこういう順序で実行する
Jobsそれをいつ起動する？

スケジュールの cron 式とタイムゾーンの具体は ep058 で扱います。

外側に Job、内側に Pipeline実際の構成イメージ

 
Job
  └─ Pipeline Task
      └─ Declarative Pipeline:  Bronze / Silver / Gold

そして Job 側で「毎日 02:00 に実行」と設定します。実行時はこう流れます。

中でどう流れるか、外からいつ始めるかDAG があれば十分では？

料理のレシピにたとえるレシピに開始時刻は無い
たとえ書いてあること対応
レシピ① 野菜を切る　② 炒める　③ 煮るDeclarative Pipelines
予定表毎朝 7:00 に料理を開始するJobs

レシピが定義しているのは何をするかとどの順番でやるかです。 「毎朝 7:00 に開始する」とは、レシピそのものには書いていません。 この「いつ開始するか」を担当するのが Jobs です。

試験対策での整理どちらに寄せるか
仕組みそこに寄せる語
Declarative Pipelines データ処理の定義 / テーブル・ビューの依存関係 / DAG / Bronze・Silver・Gold の処理フロー
Jobs 実行 / スケジュール / 起動 / オーケストレーション

一言で言えば

Declarative Pipelines = 何をどう流すか / Jobs = いつ動かすか

定義しただけでは定期実行にならない注意点

「単体でスケジュールできない」の意味

パイプラインの定義を書いただけでは、定期実行にはなりません。 そう捉えると、この表現でつまずかずに済みます。

重要なのは、Declarative Pipelines と Jobs の役割を混同しないことです。 中身と依存は Declarative Pipelines。いつ動かすかは Jobs。この境界だけ覚えて帰ってください。

Job / Task / DAG の定義そのものは ep056、スケジュール式の具体は ep058 にあります。
