Auto Loader とクラウドストレージの相性

強さの理由は「増分だけ読むから」ではありません。 増分を効率的に見つける仕組みまで持っていることが本体です。 そして、その仕組みはクラウドオブジェクトストレージを前提にしています。

Auto Loader とはクラウドオブジェクトストレージから継続的に取り込む
対象
S3。Azure Data Lake Storage。Google Cloud Storage。
やること
そこに置かれた新しいファイルを、継続的に取り込む。
強みが出る条件
ファイルイベントを利用できる場合。

ファイルイベントで見つける1000万を調べずに、100を特定する

ディレクトリ一覧という方式イベント通知は必須ではない

大規模なら通知してもらう探しに行く / 来たことを知らせてもらう
方式新着の見つけ方ファイル数が増えると
ディレクトリ一覧探しに行く一覧する処理そのものが負荷になる
ファイルイベント来たことを通知してもらう総数に引きずられない

大規模環境では、「新着ファイルを探しに行く」よりも「新着ファイルが来たことを通知してもらう」 方式のほうが効率的です。

一般のファイルシステムは対象外NAS や NFS には注意が要る

まとめと覚え方強さの本体は「読む」ではなく「見つける」

覚え方

Auto Loader は増分を読むだけではなく、増分を見つけるところまで最適化されている。

通知が使える
メリットを最大限に発揮できる。
通知が使えない
ディレクトリ一覧方式でも動く。ただしファイル数が巨大になるほど探索コストは増える。

COPY INTO との比較は ep011「COPY INTO が大量ファイルに向かない理由」で扱っています。
