import dltは古いのか

現在は from pyspark import pipelines as dp が推奨されています。 ただし import dlt が突然使えなくなったわけではありません。 既存コードは引き続き動作し、Databricks も互換性を維持しています。

昔の書き方と今の書き方結論

Python でのパイプライン定義以前 → 現在

import dlt                              # 以前
@dlt.table
def customers(): ...

from pyspark import pipelines as dp     # 現在（推奨）
@dp.table
def customers(): ...

Lakeflow Pipelines / Spark Declarative Pipelines への名称・API 整理が進んでいますが、旧 API も互換性のため動きます。

何が変わったのか製品名とAPIの両方

いつ頃変わったのか2025年春〜夏
時期公開情報で確認できること
2025年5月リリースノートで、すでに Lakeflow Declarative Pipelines という名称が使われている
2025年7月Databricks Community / 認定試験関連の案内で、Delta Live Tables からの名称変更が明示されている
その後Apache Spark 4.1 から Declarative Pipelines が Spark 側にも入る流れに合わせ、Python API も pyspark.pipelines に整理

試験教材や古いブログで import dlt が出てきても不思議ではありません。

デコレーターの書き換え2行だけ変わる

同じ処理を新旧で書く全文

import dlt                              # 以前
@dlt.table
def sales():
    return spark.readStream.table("raw_sales")
from pyspark import pipelines as dp     # 現在
@dp.table
def sales():
    return spark.readStream.table("raw_sales")

変わるのはインポートの行と、デコレーターの接頭辞だけ。関数の中身はそのままです。

役割の分け方名前に反映された
@dp.table
Streaming Table を定義する用途
@dp.materialized_view
Materialized View を定義する用途

以前は LIVE TABLE / STREAMING LIVE TABLE という名前で区別していました。それがデコレーターの名前そのものに反映され、何を作るのかが書いた瞬間に分かる形になっています。
