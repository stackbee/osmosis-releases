File arrival trigger と Auto Loader の違い

どちらも「ファイルが来たら反応する」ように見えますが、立っているレイヤーが違います。 File arrival trigger は Job を起動し、File Notification は Auto Loader に新着を知らせます。

役割が違う3つWHEN / WHAT / HOW

名前が似ているので混同されますが、この3つは別のレイヤーの仕組みです。 次の3つの問いに分けて置くと、混ざらなくなります。

仕組み問いひとことで
File arrival triggerWHEN to runいつ Job を動かす？
Auto LoaderWHAT files to ingestどの新着ファイルを取り込む？
File NotificationHOW to discover themその新着をどう見つける？

結論

File arrival trigger は Job を起動する仕組み。Auto Loader は 新着ファイルを増分で取り込む仕組み。File Notification は Auto Loader が新着ファイルを見つける方法です。

ファイル到着で Job を起こすFile arrival trigger

File arrival trigger は、Databricks Jobs の起動条件です。外部システムが /incoming/orders/ に orders_20260810.json を置いたら、Databricks が その場所を監視していて Job を起動します。

新着を増分で取り込むAuto Loader

Auto Loader は、クラウドストレージへ到着した新しいファイルを見つけて、 増分で読み込む仕組みです。

df = (spark.readStream.format("cloudFiles")
        .option("cloudFiles.format", "json")
        .load("/incoming/orders/"))

Auto Loader はこの場所の中から、どれが新着かを判別して読み込みます。

orders_001.json → 処理済み    orders_002.json → 処理済み    orders_003.json → 新着

読み込んだあとは、変換して Delta Table へ書き込みます。どのファイルをすでに処理したかという 状態はチェックポイントが持ちます。ここは ep035「Auto Loader のチェックポイントの中身」で扱いました。

新着をどう見つけるかDirectory Listing / File Notification

Auto Loader が新着ファイルを見つける方法は、大きく分けて2つあります。

方式やっていること大規模だと
Directory Listingストレージの一覧を取得し、前回との差分を見る毎回一覧を調べるコストが大きくなる
File Notificationストレージ側の File Event を通知／Queue 経由で受け取る全体を探しに行かずに済む

通知の仕組みそのもの（クラウドごとの通知基盤、Unity Catalog の External Location、 Managed File Events）は ep037「Auto Loader の Managed File Events」で扱いました。 この回では深追いせず、Jobs の File arrival trigger との対比に絞ります。 方式の選び分けは ep012 にあります。

通知は起動の仕組みではない検出であって起動ではない

File Notification は Auto Loader を起動する仕組みではない

あくまで、Auto Loader が新着ファイルを見つけるための検出方法です。 毎回全体を探しに行く代わりに通知を使う、という置き換えにすぎません。

並べて違いを見るここが最重要
項目File arrival triggerAuto Loader File Notification
所属JobsAuto Loader
目的Job を起動する新着ファイルを見つける
見ているもの監視パスへのファイル到着ファイル作成イベント
結果Job Run 開始Auto Loader が対象ファイルを認識
データ読み込みしないAuto Loader が行う
実行単位JobStreaming ingestion

矢印の先が違う、と覚えるのが早いです。File arrival trigger の矢印の先は Job の起動。File Notification の矢印の先は Auto Loader への「新着はこれ」という通知です。

両方を組み合わせる競合しない

この2つは競合する仕組みではありません。むしろ、同じシステムの中で一緒に使えます。

① 外部システムがファイルを置く   → ② File arrival trigger が検知 → ③ Job が起動
④ Job 内で Auto Loader を実行   → ⑤ Auto Loader が新着を見つける → ⑥ Delta Table へ取り込む
役どころ担当
Job を始めるスイッチFile arrival trigger
実際にファイルを取り込む処理Auto Loader

Job・Task・DAG の関係そのものは ep056「Job / Task / DAG の全体像」で扱います。

同じ事象、別レイヤーひとつの File Event、ふたつの行き先

時刻スケジュールとの違い待ち時間と空振り

File arrival trigger のメリットは、時刻ベースで Job を動かす必要がないことです。 毎時00分に動かす設定だと、こうなります。

時刻スケジュール（毎時00分）File arrival trigger
ファイルが 10:05 に着いたら10:00 起動 → 11:00 が次。55分待つ到着を検知してすぐ起動
ファイルが来ていないと10:00 / 11:00 / 12:00 と空振り実行起動しない

不要な待ち時間と、空振り実行の両方を減らせるのが利点です。

完全リアルタイムではない0秒起動ではない

「置かれた瞬間に必ず0秒で起動」ではない

File arrival trigger はイベント駆動に近い動きをしますが、監視やストレージ側の イベント伝達には多少の遅延があり得ます。

正確には、時刻スケジュールによる不要な待ち時間や空振りを減らせる と考えるのがよいです。レイテンシ保証の仕組みとして期待すると外します。

Managed File Events との関係これも検出レイヤー

現在の Databricks では、Auto Loader の新着検出に Managed File Events を使う 構成があります。以前は、クラウド側の通知インフラを利用する構成が中心でした。

クラウド従来の通知インフラ
AWSSNS / SQS
AzureEvent Grid / Queue Storage
GCPPub/Sub
 
.option("cloudFiles.useManagedFileEvents", "true")

中身は ep037 で扱った通りです。 ここで押さえるのは、Managed File Events も「Auto Loader がどのファイルを新着として 認識するか」という detection layer の話で、Job を起動する File arrival trigger とは 別物だ、という一点です。

3行で覚える試験対策

 
File arrival trigger        = WHEN to run   = Job をいつ動かす？
Auto Loader                 = WHAT to ingest = どの新着ファイルを取り込む？
File Notification / Events  = HOW to discover= その新着をどう見つける？
よくある誤解正しくは
File Notification = Job 起動 ／ File arrival trigger がファイルを読むFile arrival trigger = Job 起動。読むのは Auto Loader

一言でまとめると

File arrival trigger は「ファイルが来たら Job を始める」。Auto Loader は 「来たファイルを増分で取り込む」。File Notification は「Auto Loader がその新着ファイルを 効率よく見つける方法」。
