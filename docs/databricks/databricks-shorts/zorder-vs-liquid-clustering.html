Z-ORDERとLiquid Clusteringの違い

新しい Delta テーブルでは Liquid Clustering が推奨されています。ただし、 これは「Z-ORDER を自動実行する機能」ではありません。 Z-ORDER と従来の Partitioning を置き換える、より柔軟で継続的なデータレイアウト方式です。

置き換えであって自動化ではないまず結論

ここを間違えない

Liquid Clustering = Z-ORDER の自動実行 ではありません。Z-ORDER と従来の Partitioning を置き換える新しいデータレイアウト方式です。

従来は OPTIMIZE ... ZORDER BY (...) で、よく検索に使う列を基準にファイル配置を最適化することが多くありました。現在は、新しい Delta テーブルでは Liquid Clustering を使う方向が推奨されています。

Z-ORDERは何をしていたか近い値を寄せる

SELECT * FROM sales WHERE customer_id = 123; のような検索が多いとき、customer_id がバラバラのファイルに散らばっていると多くのファイルを読むことになります。そこで OPTIMIZE sales ZORDER BY (customer_id); を実行します。

人が明示的にチューニングマニュアルな運用

Z-ORDER では、基本的に人間が「どの列を ZORDER BY にするか」「いつ OPTIMIZE を実行するか」を考えます。

Liquid Clusteringの違いテーブル側に設定

クラスタリングキーの設定抜粋

CREATE TABLE sales (...)
CLUSTER BY (purchase_date, customer_id);

これは「purchase_date と customer_id を重要な検索軸として、データ配置を継続的に最適化してほしい」という宣言に近いものです。

Z-ORDER のような「今回この列で再配置する」という単発のチューニングではなく、テーブルのレイアウト戦略そのものとして扱えます。

従来の典型的な設計二段構え

売上テーブルで「日付での範囲検索」と「customer_id での検索」が多いとき、従来はこの2つを組み合わせる設計を考えることがありました。

従来の設計抜粋

PARTITIONED BY (purchase_date)

OPTIMIZE sales
ZORDER BY (customer_id);

役割分担はこうでした。purchase_date = Partitioning ／ customer_id = Z-ORDER。

まとめて考えやすくなる一つの方式に寄せる

マネージド化という理解どこまで正しいか

従来は人が動かす要素が強いものでした。Partition 列を決める → ZORDER 列を決める → OPTIMIZE を実行する。一方、現在は Liquid Clustering + Predictive Optimization で、データレイアウトの保守を Databricks 側へかなり任せられます。

「昔よりも人間が物理レイアウトを細かく手作業でチューニングする必要が減っている」という理解は正しいです。

ただし Z-ORDER を自動化 は ✗、新しいクラスタリング方式 が ○。Liquid Clustering 自体は単なる自動 Z-ORDER ではありません。

なぜ柔軟なのかキーを変えやすい

従来の Partitioning は purchase_date=2026-08-01/ のような物理ディレクトリ構造へ強く影響します。そのため後から「やっぱり customer_id 中心で検索したい」となると、設計変更が重くなりやすいのです。

併用するのかどちらかを選ぶ

基本的には、Liquid Clustering を使うテーブルに対して Z-ORDER を重ねて使う、という発想ではありません。Z-ORDER または Liquid Clustering、という別のデータレイアウト方式として考えます。

Liquid Clustering を採用したら、そこに ZORDER BY を追加してさらに最適化する、というものではありません。

試験向けの整理両方理解しておく
Z-ORDER
OPTIMIZE + ZORDER BY。特定列の値が近いデータを近いファイルへ寄せ、Data Skipping を効かせる
Liquid Clustering
CLUSTER BY (...)。テーブルのクラスタリングキーとしてレイアウトを管理し、Partitioning / Z-ORDER を置き換える方向

従来 Partitioning + Z-ORDER + OPTIMIZE → 現在 Liquid Clustering + Predictive Optimization。この進化として理解すると整理しやすくなります。
