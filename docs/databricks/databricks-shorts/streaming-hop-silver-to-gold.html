streaming hopとSilverからGold

hop（ホップ）とは、データがパイプラインの1つの段階から次の段階へ進む1区間のこと。 「Silver → Gold の streaming hop はどれか」と問われたら、パイプライン全体ではなく その1区間だけを実現しているコードを探します。

hopとは何か1駅ぶん進む

電車で考えると分かりやすいと思います。Raw駅 → Bronze駅 → Silver駅 → Gold駅 と並んでいて、1駅ぶん進むのが1 hop です。ですから「Silver から Gold への hop」と言われたら、その区間を実現しているコードを探せばよいことになります。

Goldらしい処理集計済みデータ

Gold は分析やレポート向けの層なので、集計済みデータを作ることが多い層です。Silver に1行1件の明細があるとき、Gold ではそれを店舗ごとにまとめます。

層中身形
SilverA/100、A/200、B/3001行1件の明細
GoldA/300、B/300店舗ごとの合計

groupBy + agg の形が出てきたら、Silver → Gold らしい処理だと考えます。

なぜcompleteか集計値が書き換わる

新しい売上が到着すると、既存の集計値そのものが変わります。A 店舗の売上合計が 300 のところへ新しい売上 50 が届くと、300 → 350 に書き換える必要があります。つまり集計結果は「新しい行を追加するだけ」では表現できません。

outputModeやること集計に使えるか
append新しい行を追加するだけ既存行を書き換えられない
complete集計結果全体を書き直す候補
update変わった集計行だけ更新する候補

正解のコードを読む2つの根拠

Silver sales → Gold newSales正解

(spark.table("sales")
    .groupBy("store")
    .agg(sum("sales"))
    .writeStream
    .option("checkpointLocation", checkpointPath)
    .outputMode("complete")
    .table("newSales")
)

正解になる理由は2つです。① groupBy + agg で店舗ごとに合計している ＝ Gold らしい集計。② writeStream + complete で、集計結果をストリーミングで更新している。

他の選択肢との違い区間で判断する
選択肢やっていることどの区間か
.withColumn("avgPrice", col("sales") / col("units"))列を追加しているだけ。データはまだ明細のままGold への集計 hop とは見なしにくい
.filter(col("units") > 0)行を絞っているだけSilver 的なクレンジング
.readStream.load(rawSalesLocation)生データから読んでいるRaw → Bronze の hop

どれもストリーミングらしく見えるので、「どの区間か」で切り分けるのがコツです。
