Control / Compute Plane と Driver / Worker を整理する

この4つは同じ階層の言葉ではありません。 Control / Compute Plane は Databricks の話、Driver / Worker は Spark の話。 そう分けるだけで、4語は一度で片付きます。

今回のテーマまず結論

分け方はこの一行

Control / Compute Plane は Databricks の話。Driver / Worker は Spark の話。

Control Plane は管理室管理・制御する側

Databricks を「管理・制御する側」。イメージとしては 管理室 / 司令部 にあたります。ここでは、たとえば次のようなものを管理します。

場所
Workspace の管理
仕事
Job の定義やスケジュール / Notebook や各種メタデータ
資源
Compute の起動・停止の制御
入口
認証や権限まわりの管理

つまり、データを大量に計算する場所そのものではなく、Databricks を動かすための管理面です。

Compute Plane は工場データ処理を行う側

実際にデータ処理を行う側。工場 / 作業現場 にあたります。Spark の処理、SQL の実行、ETL、機械学習など、実データを使った計算はこちら側で行われます。

Driver は現場監督Spark ジョブの司令塔

Driver は Apache Spark のアーキテクチャに登場する、Spark ジョブ全体の司令塔。現場監督にあたります。主な役割は次のとおり。

受け取る
ユーザーのコードを受け取る / 実行計画を作る
割り振る
処理を Stage / Task に分解する / Worker に Task を割り当てる
見届ける
実行状況を管理する / 最終結果をまとめる
df.groupBy("store").sum("sales")

この処理が来たら、Driver が「どう分割して実行するか」を考え、Worker に仕事を振ります。

Worker は作業員Task を実行する側

Worker も Apache Spark 側の役割。Driver から渡された Task を実際に実行します。実作業をする人にあたります。

2つのアーキテクチャを混ぜないここが重要

一言で覚えるまとめ

 
Control Plane 「Job をいつ動かすか、Compute をどう管理するか」
    ↓  Compute Plane  →  Apache Spark
Driver Node   「この処理をどう分割して実行するか」
    ↓  Worker A / Worker B / Worker C 「実際にデータを計算する」
レイヤーたとえ
DatabricksControl Plane = 管理室 / Compute Plane = 工場
Apache SparkSpark = 生産システム / Driver = 現場監督 / Worker = 作業員

次は Driver → Job → Stage → Task → Partition → Worker までつなげると、Databricks 上で Spark がどのように分散処理しているかがかなり見えやすくなります。
