Unity Catalog の ABAC はタグにルールを付ける

GRANT はオブジェクトを直接指定する。ABAC はタグ条件に一致したオブジェクトへ自動適用する。 タグとポリシーが分かれているから、数千テーブルでも1つのルールで済みます。

今回のテーマ属性ベースアクセス制御

ABAC は Attribute-Based Access Control（属性ベースアクセス制御）。Databricks では Unity Catalog 上のオブジェクトに付けた governed tag（管理タグ） を条件にして、アクセス制御ポリシーを動的に適用します。

従来の GRANT との違い何を指定するか

管理タグとポリシー2つの部品に分かれる
Governed Tags
ABAC の条件として使う管理タグ。classification = PII / department = HR / region = JP。通常の自由なタグではなく governed tag を使うのがポイントで、タグ自体にも誰が作れるか・割り当てられるかの管理がある
Policy
タグ条件に一致したオブジェクトへ適用するルール。Row Filter Policy / Column Mask Policy / GRANT Policy（Beta） の3タイプ

タグを付けられる人＝権限を動かせる人

タグが条件になる以上、タグの付与そのものが統制対象です。自由なタグではなく governed tag を使うのはこのためです。

行フィルタと列マスクポリシーの3タイプ
タイプ何を制御するか例
Row Filter見せる行を制御。同じテーブルでもユーザーによって見える行が変わる営業担当A → region = JP の行だけ／営業担当B → region = US の行だけ
Column Mask列の値をマスク。許可されたグループには本来の値を見せるname = Masato／email = ***／credit_card = ****-****-****-1234
GRANT Policy
Beta		タグ条件に一致したオブジェクトへ権限を動的に付与2026年時点では Beta で、利用範囲に制限がある

GRANT Policy は Row Filter / Column Mask と同じ成熟度ではありません。設計の中心に置くのは前の2つです。

PII 列を自動でマスク数千テーブルでも1つ

これが ABAC の強み。「テーブルごとに権限設定する」のではなく、「データの属性にルールを設定する」。タグと中央のポリシーで一括制御できます。

クエリ時に何が起きるか動的評価

静的に一度決めて終わりではなく、クエリ時に動的評価される。グループ所属やタグが変われば、有効なポリシーも変わります。

使い分けと一言で覚えるまとめ
仕組み役割
GRANT / REVOKE誰がどの Catalog / Schema / Table を使えるか
ABACタグを使って、見える行・列や権限を中央管理
Table-level Row Filter / Column Mask ／ Workspace Binding前者は特定テーブルだけ特殊ロジックを設定。後者はどの Workspace からアクセスできるか
 
RBAC / GRANT = 人・グループ → オブジェクト
ABAC         = 属性(Tag) → Policy → 対象データへ自動適用

ABAC = Unity Catalog の governed tag を使って、同じアクセスルールを大量のデータへ動的・一括適用する仕組み。既存の GRANT を置き換えるものではなく、組み合わせて使います。試験ではまず Governed Tag + Centralized Policy + Dynamic Enforcement という設計思想を押さえておけば十分です。
