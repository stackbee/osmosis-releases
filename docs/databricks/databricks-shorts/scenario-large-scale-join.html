大規模JOINと性能問題のシナリオ

大規模な JOIN が遅いと言われたときに、どの順番で何を疑うか。 個別の仕組みではなく、判断の道筋を1本に通すシナリオ回です。

十億行と五千万行をつなぐ基本シナリオ

orders と customers を customer_id で結合したい、という要件です。

テーブル行数性格
orders10億配ることはできない大きさ
customers5,000万これも配れない
 
SELECT ... FROM orders o
JOIN customers c ON o.customer_id = c.customer_id

効いてくるのは移動のコスト両方大きいと再配置が要る

両方が大きく Broadcast できない場合、同じ customer_id のデータを同じ Partition 側へ集める必要があります。 どの Worker にも同じ顧客の行が散らばっているので、キー単位に再配置します。これが Shuffle です（→ 第51回）。

何が起きるか中身
再配置Worker A〜D に散った同じ customer_id を、Shuffle で1か所へ集める
発生するコストネットワーク転送 / シリアライズ / メモリ / ディスク spill

結合する行の数が増えたわけではないのに遅くなる。大規模 JOIN の性能問題は、まずここを疑うところから始まります。

どの順番で疑うかこの回の主役

場面は三つに分かれる派生シナリオへの分岐

小さいマスタは配ってしまう派生 1/3 — Broadcast Join
テーブル行数扱い
orders1億動かさない。各 Worker の Partition のまま
regions50全 Worker へ配る

地域マスタを JOIN するだけなら、大きい orders を Shuffle するより、小さい regions を各 Worker へ配るほうが効率的です。

大きいテーブルを動かさず、小さいテーブルを全 Worker へ配る。 Spark が統計情報から自動判断する場合もあれば、AQE が実行中のサイズを見て戦略を変える場合もあります。 自動と手動の切り分けは第53回で扱いました。

匿名顧客に集まる派生 2/3 — Data Skew

customer_id = 0 を匿名顧客として使っていると、そこだけ桁が変わります。 1つの Shuffle Partition だけ極端に大きくなり、症状は Task の実行時間に出ます。

見る場所出ている値
customer_id 別の件数1001 は10万行 / 1002 は12万行 / 1003 は9万行 —— ところが 0 だけ2億行
Task の実行時間A・B・C は各2分 —— ところが D だけ35分

クラスタ全体では空いている Worker があるのに、一部の Task 待ちになります。 偏りそのものは第63回で扱いました。この場面では、必ず一度は Skew を疑う——押さえておくのはそこです。

集計でも同じことが起きる派生 3/3 — GROUP BY

店舗別・商品別に大量データを集計する場合です。

SELECT store_id, product_id, SUM(amount)
FROM sales GROUP BY store_id, product_id

同じキーを同じ Partition に集めるため、ここでも Shuffle が発生します。 つまり JOIN だけの話ではありません。GROUP BY、DISTINCT、ORDER BY、repartition()—— どれも Shuffle を意識する対象で、疑う順番はそのまま使えます。

実行しながら作戦を変える停留所 ⑤ — AQE

ここまでの手当ての一部は、AQE が実行時統計を使ってやってくれる場合があります。

実行中に分かったことAQE の手
実際には片側が小さいSort Merge Join → Broadcast Join へ変更
小さい Shuffle Partition が大量まとめて Task 数を適正化
一部の Partition だけ巨大Skew 対策

AQE の中身は第62回で扱ったので、ここでは深追いしません。 大事なのは、AQE が効いているかどうかも、疑う順番の中の一つの停留所だということです。

計算量ではなく移動量覚え方

大規模 JOIN の性能問題 = 「計算量」だけではなく「データをどれだけ Worker 間で動かすか」を見る。

流れで覚えるなら、JOIN → Shuffle → Broadcast → Skew → AQE。 試験でも実務でも、この順に並べると整理しやすくなります。

遅いと言われたら、台数を足す前に、動かす量を見る。それが今回の筋です。
