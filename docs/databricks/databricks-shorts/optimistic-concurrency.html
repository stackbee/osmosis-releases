Delta Lake の同時更新は Optimistic Concurrency Control

ロックで順番待ちさせるのではなく、先に処理して commit 時に競合チェックする。 残るのは、早く始めた変更ではなく、先に有効な commit が成立した変更です。

今回のテーマ結論から

複数のユーザーが同じテーブルを同時に更新しようとしたとき、Delta Lake はロックで順番待ちさせません。使うのは Optimistic Concurrency Control（楽観的同時実行制御） です。

Row-level concurrency

共通しているのは同じ対象に触るかどうか。そのうえで、最近の Databricks では row-level concurrency により、同じファイルを触っていても異なる行なら競合を減らせる場合があります。ただし、今回のように本当に同じ行を同時変更するなら競合制御が必要になります。

DEA 向けの覚え方

Delta Lake はロックで順番待ちさせるのではなく、Optimistic Concurrency Control で並行実行し、commit 時に競合検出する。先に有効な commit が成立した変更が残り、競合した後続処理は失敗・再試行になる。
